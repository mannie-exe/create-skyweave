# Shader lab

This authoring workspace acquires pinned shader inputs through empack and invokes
Compat's file-only Java engine. Recipients use that same engine before Iris opens
a shader. Python orchestrates author builds; it does not implement shader edits.

From the repository root, with Java 21, Python 3.11+ and empack:

```sh
python3 tools/shader-lab/build.py
python3 tools/shader-lab/build.py --check
```

For an unpublished engine, pass `--runner /path/to/skyweave-compat.jar`. The lab
pins a released runner and Gson for ordinary authoring and CI. Neither helper is
shipped as an extra client mod. `dist/` contains complete, deterministic review
ZIPs. Public modpack exports reference original provider inputs instead.

## Recipes

`overrides/client/config/skyweave-shaders/recipes/` is the canonical source for
patch versions, ordered operations, exact input hashes, runtime requirements,
output names and expected payloads. The combined Skyweave correction is versioned
independently of its inputs. Its current Complementary output is:

`Complementary Unbound r5.9.3 + Euphoria 1.10.5 + Skyweave 0.2.0.zip`

Skyweave Glass remains the material-classification patch within that result; its
0.1.0 material report is unchanged by the environment corrections.

The two qualified chains are Complementary → Euphoria → Skyweave, and
BSL → Colorwheel → Skyweave. BSL outputs
`BSL_v10.1.8 + Clrwl_1.0.5 + Skyweave_0.2.0.zip`. They use bounded archive overlays, the exact Euphoria
binary engine and authored text edits with source/occurrence preconditions.
Recipes cannot run commands or choose executable plugins. Keep upstream material
changes in the recipe, rather than recreating them in Python or Java constants.

The Java `ShaderCli` consumes the same recipe directory, input layout, handlers,
cache and archive writer used at runtime. The lab stages that layout under
`.cache/recipient/` and compares exact generated bytes for `--check`.
`materials.py` separately checks the qualified Create model bindings and alpha
classification against the recipe's material report. This is evidence for the
chosen policy, not a second transformation implementation.

## Runtime ownership

| Location | Owner |
| --- | --- |
| `shader-inputs/` | Empack-managed original shaders and Colorwheel patch payload |
| `mods/` | Runtime integrations, including Euphoria and Create |
| `config/skyweave-shaders/recipes/` | Authored managed recipes |
| `.cache/skyweave-shaders/` | Runner receipts, verified cache and intermediates |
| Named generated ZIPs in `shaderpacks/` | Runner |
| Shader `.txt` options | Iris/player, with pack-provided seeds |

Bindings place original inputs outside Iris's list from installation onward.
Colorwheel Patcher is read as a verified archive, without loading its mod. The
Colorwheel runtime and Euphoria runtime remain installed. Generated shader ZIPs
are not exact empack-managed files, so runtime generation does not create repair
conflicts. Server exports contain no shader recipes, inputs or outputs; Compat
has no client shader hooks on a dedicated server.

A cache key covers canonical recipe data, actual input digests and engine revision.
Receipts also verify output bytes. A missing/corrupt result can be restored;
unchanged launches perform no shader writes and need no downloads. An instance
lock and atomic publication protect rebuilds. The Compat configuration screen
shows per-recipe state and provides **Rebuild shaders**, closing Iris's archive
before publication. Errors retain previous verified bytes, but an incompatible
or failed selected recipe is not silently loaded as an old or baseline shader.

Name changes migrate only that recipe's recorded selection. Compatible presets
are copied only to an absent destination or a recipe-qualified unchanged seed; explicit option renames belong in the
recipe. Enablement and other shader selections are preserved. Unrelated shaders
and presets are never retired by directory cleanup.

## Window materials

The pinned Euphoria output places Create windows broadly in the translucent
layer. The Skyweave correction qualifies 38 targets: 32 binary-alpha windows use
cutout; six partially transparent windows/panes remain blended. The six are
birch, weathered iron and ornate iron; ornate iron has two alpha-149 glints.
The generated `skyweave-glass.json` records the source texture evidence.

Partial-alpha windows retain their original lighting IDs. Opaque frame texels
lose generated glass reflections under built-in PBR; custom PBR stays authoritative.
Shader stained-glass edge rewriting skips these windows because Create owns their
connected textures. The shader correction does not alter collision, neighbor
culling or backface geometry; those are independent Compat adaptations.

## Island environment

Both chains also consume narrow Compat uniforms: `skyweaveWorld`,
`skyweaveVoidVisuals` and `skyweaveOpenSky`. In marked worlds they replace selected
vanilla-altitude cave/bedrock fades with available exposure and light. Foreign
worlds, underwater rendering, genuine enclosed rooms and status effects retain
their own paths. This is separate from the glass material classification.

Native cloud height comes from Compat's dimension-effects provider; independent
shader cloud layers need not share that height. Iris precipitation uses the same
reference-temperature policy as native island weather. Do not globally rescale
camera altitude, sea level or every atmospheric option. Unknown shaders do not
automatically gain these corrections. Photon remains source/config reviewed on
unsupported Apple hardware.

## Updates

Run `empack --workdir tools/shader-lab outdated` to inspect updates. Review and
change exact pins deliberately. Keep root and lab Create/Euphoria pins aligned.
For an engine update, qualify the candidate through `--runner`, publish Compat,
then update the lab and playable manifest to its verified released artifact.

For BSL, inspect Colorwheel Patcher's `config.json`, advertised shader version and
`patches/BSL.zip`. For Euphoria, recheck the shaded BSDIFF API, normalized TAR
headers/directories/style, source preconditions, material IDs and runtime scanner
hooks. The reviewed Euphoria engine digest is an executable allowlist in Compat;
a recipe hash alone cannot authorize a different engine. Recheck Create alpha and
model bindings, including resource-pack replacements. Recheck uniform registration,
per-frame updates, dimension switching, disabled controls and low-open-sky versus
real-cave behavior. Bump the combined Skyweave version for environment changes;
bump the material patch when classification changes. Regenerate provenance,
output names and preset paths together.

Regenerate with the shared engine, qualify payload hashes, compare recipient and
author bytes, and verify native startup/reload and moving geometry. Update the
shader configuration register for changed presets or recipes. Empack reference
exports must contain source references and recipes, with no prebuilt merged
shader. Retire corrections only after verifying the selected upstream equivalent.
Keep the existing quality/enablement policy; Photon remains unsupported on Apple
hardware rather than receiving a local workaround.

## Distribution

Generated review ZIPs preserve upstream notices. Compat contains no shader or
patcher binaries. The modpack distributes provider references and authored
corrections; complete results are generated within the recipient installation.
This changes delivery, not upstream ownership. Euphoria's modified-pack and
Complementary/BSL distribution terms still apply to any proposed public hosting
of complete outputs. Do not attach lab output ZIPs to releases as if generation
itself granted redistribution permission.
